# PRD-B conformance

Every requirement in PRD-B, where it lives, and how it is checked. Generated by
hand and kept honest by `tests/test_part_b.py`, which fails the build when a
requirement loses its answer.

`pytest tests/test_part_b.py` — 67 tests.

Legend: **met** = implemented and covered by a test. **partial** = implemented,
with a stated limit. **process** = a commitment a human keeps; the test asserts
the commitment is documented, which is the most a test can honestly do.

## Corrections made while measuring

B-R27 says: never weaken a check to make a case pass — fix the check and say so.
Four checker faults were found by pointing the ledger at real repositories, and
all four were fixed in the extractor rather than filtered out of the output.

1. **`@mock.patch("x.y.Z")` was read as a `PATCH` route.** Every test file in
   redash produced phantom routes, which then poisoned downstream no-route
   findings. Fixed by requiring a route path to start with `/`.
2. **Source-level env writes were invisible.** `os.environ["X"] = ...` at import
   time is a writer; redash's `tests/__init__.py` sets seven names and reads them
   back, and all seven were reported as never set. Fixed by scanning source for
   writes as well as config for them.
3. **Dockerfiles were not read as a writer source.** `ENV DISPATCH_BUILD=...`
   sets the value that dispatch was reported as missing. A-R4 lists five writer
   sources; the intent is "set nowhere", and a Dockerfile is somewhere.
4. **`if "X" in os.environ:` was not recognised as a default.** It is the third
   way to write a fallback, alongside `os.getenv("X", d)` and `?? d`.

Two confidence corrections, same rule:

5. **Zero-caller findings drop to low when no consumer call in the tree resolved
   to any route.** If we could not read the consumer side at all, "no caller"
   describes our extractor, not the code.
6. **Ambient names are exempt from the env check.** `CI`, `HOME`, `PATH`,
   `NODE_ENV`, `GITHUB_*` and similar are provided by the runtime, not by
   anything a repository commits. The exemption list is in
   `irus/extract/env.py::AMBIENT` and is readable, not hidden.

Effect on the five-repo run: 233 findings with 12 high-confidence, down to
**197 findings with 0 high-confidence**. `irus check` exits 0 on all five repos —
which is the correct behaviour, since none of them contains an agent-introduced
seam mismatch.

## Known limits, stated rather than hidden

- **Payload matching is narrow by design** (PRD-B §7 first risk): literal object
  bodies, `JSON.stringify` of a literal, and `FormData`. `JSON.stringify(payload)`
  where `payload` is a variable is reported as unreadable, not guessed.
- **No TypeScript type resolution.** The consumer scanner reads call sites
  literally. The `ts-morph` upgrade path in the build plan is unstarted.
- **`include_router(prefix=...)` is unresolved.** Only `APIRouter(prefix=...)` is
  followed, so dispatch's route paths appear without their mount prefix. This is
  why its 129 zero-caller findings sit at low confidence.
- **Flask, Django, and Express producers are not extracted.** Redash is Flask, so
  zero routes are found there — correctly quiet rather than wrongly loud.
- **YAML is read with an indentation scanner, not a parser**, to avoid a runtime
  dependency. Block and inline-list forms are handled; anchors and merge keys are
  not.
- **Stage 2 tier 2 is implemented but undriven.** `prove.tier2` takes a client
  factory, a transaction, and a row counter; no harness builds those for a target
  repo yet, so `--prove` runs tier 1 only.
